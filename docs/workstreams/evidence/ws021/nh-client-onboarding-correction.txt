BOUNDED IMPLEMENTATION
* Add an explicit Set up workspace action to the existing platform client detail page
  only for an active client/org with no contexts and organizations.manage authority.
* Server route and new ws021_prepare_client_context RPC independently verify canonical
  platform administration and exact active client-account/organization ownership.
  It locks the target, creates one deterministic first context only when none exists,
  reuses an active context on repeat, and refuses inactive or conflicting contexts.
  It inserts an audit event atomically. Account/org rows, connections and offers are
  never rewritten. The NH context ID would be client-ab757103-4ad9-4fd8-a3f1-3f5adaee9b03;
  this is a proposed deterministic identifier, NOT an already-created production row.
* Add an opt-in Orders-only invitation control. Existing ordinary invitation behavior
  is unchanged. Restriction requires users.invite AND users.manage_permissions plus
  canonical platform-admin authority; server and RPC both enforce the checks.
* A protected private-by-RLS invitation policy row is inserted in the same transaction
  as the existing invitation/delivery claim. It cannot be removed via a browser API.
* Existing verified-email invitation acceptance remains in use. A scoped membership
  INSERT trigger adds two existing permission-override records, both deny, for exactly
  financials.view and orders.view_financials on that invitation's NH membership.
  Failure to persist either denial rolls back the entire acceptance transaction.
  No period exists where an accepted restricted membership commits without its denials.
  No shared role, other memberships, RLS policies or historical records are edited.
* Only successful acceptance sets the signed active-organization cookie for the current
  authenticated user and accepted org, then clears stale Business Context selection.
  Cookie remains HttpOnly, SameSite=Lax, Secure in production. Failed acceptance sets none.
