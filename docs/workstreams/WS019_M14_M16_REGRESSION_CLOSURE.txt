Independent implementation inspection before corrections
- ui/components/connections/governed-provider-actions.tsx: discovery is GET;
  prepare POST sends only operation; confirm POST sends operation and opaque intentId.
  Confirm requires a deliberate onClick after prepared state. Confirmed state says
  "Confirmed — not executed". No provider execute endpoint is called by this component.
- ui/app/api/actions/provider-prepare/route.ts and provider-confirm/route.ts:
  authenticated application session, Shopify-only allowlist, reject unknown body fields,
  revalidate discovery readiness. Prepare issues intent, confirm issues confirmation;
  neither calls execution. Confirmation response explicitly sets executionAvailable:false.
- ui/lib/mcp/action-service.ts: prepareApprovedShopifyControlledProof requires action
  access/policy and server-resolved plan; prepare validates exposure and issues expiring
  durable intent with executionAvailable:false. confirm requires action access/policy
  and binds intent to the exact operation/target kind. Execution is a separate method.
- ui/lib/mcp/provider-action-discovery.ts: capability/contract/policy assessment and
  session permission checks precede session-scoped provider readiness. Organization
  comes from activeOrganization. Handoff arguments are empty. No preparation,
  confirmation, authorization consumption or execution occurs in discovery.
- ui/lib/mcp/tool-adapter.ts: discovery inputSchema is an empty object with
  additionalProperties:false; dispatcher assertKeys(args,[]) precedes read-service call.
- ui/lib/mcp/production-v1-policy.ts, action-capability-registry.ts and
  provider-action-contract.ts: Commas engineering-ready/not-live-proven remains
  non-executable. Shopify is only the named controlled_webhook_create_delete_proof,
  controlled_proof_only, reversible, provider_read_back, actions.execute and explicit
  confirmation required. Controlled proofs cannot resolve from reusable action plans.
  Matching durable intent/authorization/replay metadata and policy are required.
- ui/lib/mcp/durable-execution-gate.ts retains issue/find, atomic consumption,
  exact persisted replay result and rejection when authorization/result is unavailable.
These are local implementation observations, not a new production certification.
