## Read-only command

From `api/`, with existing server-only Supabase read credentials in the process environment:

```sh
npm run dry-run:nmi-refunds -- --output=/private/tmp/nmi-refund-manifest.json
```

The command performs HTTP `GET` reads only. The optional manifest is created with mode `0600` and exclusive-create semantics. It contains provider transaction identifiers and evidence hashes, but no source XML or customer PII. Do not write the manifest into the repository.

## M1.3D RETURN-reference certification addendum (2026-09-25)

The classifier now recognizes only `RETURN [A-Z0-9]{6}` when all of that settlement corroboration is present. Missing settlement, mismatched settlement amounts, nearby response strings, or other incomplete combinations remain ambiguous.

## Scope gate

The authorized operator has approved all ten named legacy NMI platforms as belonging to NH Discounts LLC. NH Discounts LLC is not yet an onboarded TraceKit production tenant, and the existing internal `TraceKit` organization must not be used as temporary ownership. The corpus scope state is therefore `BLOCKED_PENDING_CLIENT_TENANT_ONBOARDING`, not unresolved ownership.

The credential rows exist and use key version 2, but:

- legacy credential metadata is empty;
- historical `platform_orders` have no `account_id`, `organization_id`, `connection_id`, or `provider_account_id`;
- no exact `commerce_provider_connections` mapping exists; and
- no exact `commerce_provider_accounts` mapping exists.

Names and labels are not ownership evidence. Financial writes remain prohibited until all four dimensions are deterministically resolved and joined.

The generic `nmi` credential remains a legacy alias on hold and is excluded from this approval and dry run.
